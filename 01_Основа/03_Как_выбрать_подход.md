# Как выбрать подход

**Статус:** основной.

Сначала определяется природа изменения. Затем выбирается минимальный набор
артефактов и проверок.

| Вопрос | Если ответ «да» |
|---|---|
| Меняется наблюдаемое поведение продукта? | Использовать SDD и человеческий review требований |
| Восстанавливается уже утверждённое поведение? | Исправлять как дефект от существующего требования |
| Есть сложное детерминированное правило? | Применить TDD к чистому вычислительному ядру |
| Нужны понятные бизнесу примеры поведения? | Использовать BDD или ATDD |
| Есть сложная предметная модель и конфликт терминов? | Использовать элементы DDD |
| Принимается долговечное техническое решение? | Записать ADR |
| Оценивается недетерминированный ответ модели? | Создать eval |
| Повторяется платформенная механика? | Рассмотреть шаблонизатор или runtime |
| Нужно найти связи и область влияния? | Использовать граф как индекс |

Метод не вводится ради единообразия. Его стоимость должна быть ниже риска,
который он уменьшает.
