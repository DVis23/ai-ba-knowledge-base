# Agents

Делегирование подзадачи в изолированный контекст. Subagent получает собственное окно — основной контекст не засоряется промежуточным шумом.

## Зачем существует

1. **Окно конечно.** 2000 строк tool-результатов на одну находку — гарантированная компакция через два шага. Агент возвращает только итог.
2. **Параллельность.** Несколько независимых веток исследования = несколько агентов в одном сообщении.
3. **Изоляция инструментария.** Agent может иметь свой набор tools (write-запрет для аудитора, MCP-доступ только у одного типа).
4. **Чистый «свежий взгляд».** Agent не видит твоих ранее принятых решений — годится для независимой проверки.

## Когда агент, а не основной поток

- **Много шума на единицу полезного вывода**: чтение 20 файлов ради одного факта → Explore.
- **Независимые ветки** → параллельные агенты в одном сообщении.
- **Цель ещё не определена**, нужно разведать перед планом → Plan.
- **Тяжёлый ответ**: 2000+ строк tool-вывода не должны попасть в основное окно.
- **Второе мнение** на собственное решение → агент без твоего контекста.

## Когда НЕ агент

- Известна точка: путь к файлу, имя символа → прямой Read/Grep, не делегирование.
- Задача требует продолжения диалога с пользователем — агент возвращается одним сообщением.
- Меньше 2-3 шагов с понятной целью — overhead запуска дороже выигрыша.
- Цель требует синтеза из twin-доменов, которые знаешь только ты — агент потеряет половину контекста.

## Типы (общие)

|Тип|Назначение|Особенность|
|---|---|---|
|**Explore**|Быстрый read-only поиск файлов/символов|Не годится для аудита и кросс-файлового анализа — читает фрагментами|
|**Plan**|Проектирование плана|Возвращает шаги, тред-оффы, критичные файлы. Не пишет код|
|**general-purpose**|Что не легло на специализированные|Полный набор tools|

Конкретный проект добавляет свои: `code-reviewer`, `security-review`, `build-validator` — см. `.claude/agents/` или системные промпты.

## Как формулировать промпт агенту

Агент не видит твоего контекста. Промпт = брифинг для нового коллеги.

- **Цель и зачем** одной фразой: «найди X, потому что мне нужно решить Y» — не просто «найди X».
- **Что уже исключено** — экономит шаги и предотвращает повтор твоей работы.
- **Формат ответа**: «отчёт под 200 слов», «список путей file:line», «да/нет + 2 строки обоснования».
- **Не делегируй понимание**. «Исправь баг в X:42, заменив A на B» — синтез на тебе. «Найди и проанализируй проблему, потом исправь» — синтез на агенте, риск галлюцинаций.

## Изоляция через worktree

Опция `isolation: "worktree"` создаёт временный git worktree.

- **Полезно когда**: несколько агентов правят пересекающиеся файлы; сравниваешь два подхода без отката.
- **Не нужно когда**: read-only исследование; одна правка с понятным контрактом.
- **Откат**: worktree удаляется автоматически, если агент не сделал изменений. Если сделал — путь и ветка возвращаются в результате.

## Принципы дизайна

|Принцип|Что значит|Что ломается без него|
|---|---|---|
|**Брифинг, не команда**|Объясняй цель и контекст, а не только шаги|Агент следует инструкции буквально и попадает мимо|
|**Узкий формат ответа**|Заранее проси формат («список путей», «да/нет + 1 строка»)|Возвращает простыню — экономия окна теряется|
|**Не делегируй синтез**|Решения остаются на тебе|Агент придумывает связи, которых нет в коде|
|**Параллель — в одном сообщении**|Несколько Agent в одном tool-call|Последовательный запуск убивает выигрыш по времени|
|**Проверяй, что агент сделал**|Summary агента описывает намерения, не факт|Считаешь работу сделанной, а правка не применилась|

## Связь со skills и MCP

- Skill вызывает агента, когда внутри шага нужно длинное исследование — не дублируй логику Explore в самом skill. См. [Skills.md](04_Skills.md).
- Agent наследует доступные tools, включая MCP. См. [../02_Вспомогательные/03_MCP.md](../02_Вспомогательные/03_MCP.md).
