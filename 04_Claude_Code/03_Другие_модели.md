# Подключение других моделей

Claude Code — дефолтная среда этой базы, но цикл не привязан к одной модели. Фреймворк держит структуру (форму + проверки), поэтому LLM — **сменяемый движок**, а не система. Это даёт выбор по цене и возможностям, а локальные модели — ещё и приватность данных (важно под NDA).

## Чат против интеграции

|Режим|Как используется модель|Потолок|
|---|---|---|
|**Чат**|оракул, копипаст руками|не масштабируется на проект|
|**Интеграция**|модель приводит в действие skills / агентов / кодоген, фреймворк проверяет форму|весь цикл|

«Полное» подключение — это интеграция: модель становится функцией в пайплайне, а не собеседником.

## Уровни подключения

|Уровень|Что делает модель|Как|
|---|---|---|
|**API в пайплайне**|шаг-функция (рафинирование, генерация артефакта)|вызов API из скилла/скрипта|
|**Агент с инструментами**|вызывает tools (read/write/grep/bash), не только текст|агент-фреймворк|
|**Кодоген / IDE**|автодополнение и правки в проекте|IDE-плагин / CLI-харнес|
|**Оркестрация**|несколько моделей, роутинг по задаче|шлюз/роутер|

## Как подключить конкретную модель

- **OpenAI-совместимый эндпоинт.** DeepSeek, Qwen и многие другие отдают OpenAI-совместимый API. Направляешь любой агент/SDK на `base_url` + `api_key` — и модель работает как движок. Большинство агент-фреймворков это принимают из коробки.
- **Через прокси/роутер.** Шлюз (LiteLLM, OpenRouter) даёт единый OpenAI-совместимый вход к десяткам провайдеров; смена модели = смена имени, без правки кода.
- **Локально.** Ollama / vLLM / LM Studio поднимают OpenAI-совместимый сервер с DeepSeek/Qwen/Llama на своём железе. Данные не покидают периметр — для NDA-проектов это ключевое.
- **В харнесе.** Claude Code заточен под модели Anthropic (напрямую и через Bedrock/Vertex). Для других моделей берёшь агент-фреймворк с OpenAI-совместимым клиентом или прокси-слой. Skills, спеки и граф от харнеса не зависят — это markdown + CLI, работают с любой моделью.

## Роутинг по стадиям цикла

Разным стадиям — разные модели; выбираешь по требованию, не по привычке:

|Стадия|Что нужно от модели|Разумный выбор|
|---|---|---|
|Рафинирование встреч|объём, дёшево|быстрая/дешёвая (можно локальная)|
|БА-генерация, спеки|рассуждение, следование схеме|сильная|
|ИИ-кодинг|сильная по коду|сильная|
|Чувствительные данные|приватность|локальная (NDA)|

## Что не меняется

Форма и проверки одинаковы независимо от модели: линтер графа, валидатор спек, типы и тесты кода проверяют вывод **любой** модели. Поэтому модель — commodity, а ценность — в [фреймворках](../03_Фреймворки/). Модели можно смешивать и менять, не переписывая процесс.
