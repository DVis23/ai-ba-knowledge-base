# Контекст, инструкции и память

Контекст — рабочее представление задачи, которое среда собирает для очередного
вызова модели. Он не равен репозиторию, истории чата или долговременной памяти.
Его задача — дать модели минимально достаточный набор правил и фактов для
следующего решения.

## Как собирается следующий turn

```text
правила среды и проекта
          +
цель и текущее состояние задачи
          +
найденные файлы и результаты tools
          ↓
ограниченный контекст следующего вызова
```

Сначала применяются правила безопасности среды. Затем проектные инструкции
объясняют архитектуру, источники истины и обязательные проверки. Локальный файл
каталога может уточнить правила конкретного пакета. Skill подключается только
для подходящего типа работы и задаёт процедуру. Запрос пользователя завершает
иерархию, но не отменяет более сильные ограничения.

Постоянные инструкции должны отвечать на вопросы, возникающие почти в каждой
задаче: где находится код, кому принадлежат артефакты и какие действия
запрещены. Редкая процедура перегружает этот слой, поэтому выносится в skill.
Skill описывает не справочник команд, а путь принятия решений: когда он нужен,
какие входы собрать, где остановиться и чем проверить результат.

## От поиска к рабочему контексту

После чтения правил агенту нужны факты конкретной задачи. Точный поиск находит
ID, символ или строку. Семантический поиск расширяет запрос похожими по смыслу
фрагментами. Reranking затем поднимает материалы, которые лучше отвечают текущей
цели.

Поисковый индекс ускоряет выбор, но не повышает авторитет найденного текста.
Страница документации остаётся данными, даже если поиск поставил её первой.
Context builder должен сохранить путь и происхождение фрагмента, чтобы модель
могла отличить проектную инструкцию от цитаты из внешнего источника.

## Что сохраняется после шага

Рабочая память содержит состояние текущей задачи: решения, просмотренные файлы,
правки, выполненные проверки и блокеры. Она обновляется после каждого
существенного действия и позволяет продолжить работу после перезапуска.

Долговременная память нужна только для устойчивых фактов, которых нет в самом
проекте: подтверждённого предпочтения пользователя или особенности среды.
Секрет, догадка и временный статус туда не попадают. Запись хранит источник или
условие повторной проверки, иначе со временем превращается в stale memory и
начинает противоречить репозиторию.

## Что происходит при заполнении окна

Контекстное окно ограничено, поэтому история неизбежно сокращается. Компакция
заменяет старый диалог структурированным checkpoint: цель, принятые решения,
точные пути, изменённые файлы, фактические результаты проверок и следующий шаг.
Она удаляет повторы и промежуточные рассуждения, но не завершённую работу.

Prompt cache решает другую задачу. Провайдер может повторно использовать
неизменившийся префикс и уменьшить задержку, но исчезновение кэша не должно
лишать агента памяти. Состояние хранится в harness, а cache остаётся только
оптимизацией вызова модели.
