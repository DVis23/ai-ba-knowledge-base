# Граф

Документация — не плоский список файлов, это сеть. Любая ссылка по ID (`ART-19 → SPEC-04 → IMPL-12`) — ребро. Любой артефакт — узел. Когда у тебя 350+ артефактов и 2500+ связей, ты либо строишь граф, либо теряешь контроль.

Граф решает четыре задачи, которые на «куче markdown» неразрешимы:

1. **Impact analysis.** «Что сломается, если я поменяю `ART-19`?» — это запрос к графу, BFS вниз. Без графа = ручной grep + молитва.
2. **Audit целостности.** Висячие ссылки, циклы, сироты, мосты, bottleneck-узлы — всё свойства графа. Текстом не выявляются.
3. **Coverage.** «Все ли атомарные артефакты покрыты спеками? Все ли спеки трассируются до реализации?» — это reachability/проекции на графе.
4. **Контекст для LLM.** Подграф вокруг узла = компактный релевантный контекст. Без графа LLM либо читает всё (контекст переполнен), либо не то (галлюцинации).

## Что отличает «хороший» граф от «никакой»

Не любая сеть связей — полезный граф. Полезный имеет:

1. **Одну семантику узла.** Все узлы — артефакты, или все — сущности. Не микс.
2. **Типизированные рёбра.** Не «связано», а `implements / refines / triggers / depends-on`. Тип ребра несёт смысл.
3. **Направленность, где она есть.** `<требование> → <реализация>` ≠ `<реализация> → <требование>`. Если направление не определено — это не граф зависимостей, а ассоциация.
4. **Стабильные ID узлов.** Переименование = новый узел = граф рассыпался. Поэтому ID, а не имена.
5. **Источник истины.** Граф строится из артефактов, а не правится вручную. Иначе он расходится с реальностью на следующий день.
6. **Машинно-генерируемый.** CLI вроде `graph-tool import` пересобирает БД из markdown. Если граф рисуется руками — он мёртв через неделю.
7. **С запросами, а не только картинкой.** Картинка на 600 узлов нечитаема. Ценность — в `impact`, `path`, `anomalies`, `coverage`, а не в визуализации.

## Что граф даёт именно LLM

Это отдельный пункт, потому что для людей графы — про картинки, а для LLM — про контекст:

- **Подграф как контекст.** `graph-tool node ART-19` возвращает узел + соседей с `файл:строка`. LLM подгружает только это, не весь репозиторий.
- **Стабильные адреса.** Модель не пересчитывает заново «о чём этот файл» — есть ID и его связи.
- **Валидация генерации.** LLM сгенерила `SPEC-XX → ART-19`. Граф проверяет: `ART-19` существует, `SPEC-XX` уже занят, ссылка не циклическая.
- **Семантический поиск + графовый обход.** FTS5 находит точку входа, обход графа достраивает контекст по связям. Это лучше любого embedding-поиска в одиночку.

## Связка с фреймворком и skill-ами

Три уровня снова смыкаются:

- **Фреймворк** даёт схему: какие типы узлов бывают, какие рёбра допустимы, какие ID валидны.
- **Skill** заполняет схему: создаёт узлы и рёбра по процедуре.
- **Граф** хранит результат и проверяет его на консистентность.

Без графа фреймворк превращается в стопку шаблонов, а skill-ы — в генератор файлов, которые никто не связывает. Уберите граф — `lint --impact ART-19` станет невозможным, и вы вернётесь к ручному ревью на сотнях артефактов.
