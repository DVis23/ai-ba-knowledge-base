# Триада: Framework + Skill + Graph

Три ноги одного стула. Каждая отдельно работает плохо, втроём — движок **документной** семьи фреймворков (БА, спеки, архитектура). [Кодовые фреймворки](06_Код_фреймворк.md) устроены иначе. Место триады в общей картине → [Что такое фреймворк и граф](../01_Концепция/02_Фреймворк_и_граф.md).

> «Фреймворк» в этой триаде — слой-схема. Здесь под ним подразумевается [**БА-фреймворк**](03_БА_фреймворк.md) (типы артефактов, ID, рёбра); все примеры ниже — на нём. По тем же правилам в триаду встают спек- и архитектурный фреймворки.

## Роли

|Слой|Что даёт|Без него|
|---|---|---|
|**Фреймворк**|Схему: типы артефактов, допустимые рёбра, валидные ID|Skill изобретает структуру каждый раз|
|**Skill**|Процедуру наполнения схемы|Шаблоны мёртвые, фреймворк — стопка markdown-файлов|
|**Граф**|Хранилище результата + проверки целостности|Impact-анализ невозможен, расхождения накапливаются|

## Где смыкаются

- **Фреймворк** (схема) → [БА-фреймворк](03_БА_фреймворк.md): типы артефактов и ID-схемы.
- **Skill** (процедура) → [04_Claude_Code/01_Основные/04_Skills.md](../04_Claude_Code/01_Основные/04_Skills.md) (механика) + конкретные `ba-*` skills проекта.
- **Граф** (хранилище + проверки) → [Граф](02_Граф.md): граф-инструмент над артефактами.

## Конвейер на реальном примере

БА-пайплайн (пример конвейера): каждый шаг — отдельный skill, каждый артефакт — узел графа, каждая ссылка по ID — типизированное ребро.

|Шаг|Skill (процедура)|Артефакт (узел)|Что проверяет граф|
|---|---|---|---|
|Встреча → рафинат|`ba-refine-meeting`|рафинат `[D]/[R]/[PAIN]`|все факты сохранены (самопроверка)|
|Рафинат → стейкхолдеры|`ba-generate-stakeholders`|`ST-XX`|ID уникальны|
|ST → требования|`ba-generate-requirements`|`BR.X`|нет сирот|
|Требования → процессы|`ba-generate-processes`|`BP-XX`|ссылки на `BR.X` валидны|
|Процессы → правила|`ba-generate-rules`|`BR-XX`|нет висячих ID, нет циклов|
|Правила → функции|`ba-generate-functions`|`BF.XX`|coverage: каждое `F` покрыто `BF`/`BR`|

Поток в процессе → [02_БА_документация](../02_Процесс/02_БА_документация.md).

## Что ломается при выпадении одного

- **Убрать фреймворк** → skill каждый раз изобретает форму. Поля у похожих артефактов разные, граф не строится.
- **Убрать skill** → шаблоны мёртвые. Фреймворк описывает, что должно получиться, но не как. Каждый артефакт собирается вручную.
- **Убрать граф** → impact-анализ невозможен. После правки правила неизвестно, какие процессы и спеки протухли. На сотнях артефактов и тысячах связей ручной ревью бесполезен.
