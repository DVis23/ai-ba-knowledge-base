# Триада: Схема + Skill + Граф

Три ноги одного стула. Каждая отдельно работает плохо, втроём — движок **документной** семьи фреймворков (БА, спеки). [Кодовые фреймворки](06_Код_фреймворк.md) устроены иначе. Место триады в общей картине → [Что такое фреймворк и граф](../01_Концепция/02_Фреймворк_и_граф.md).

> В проектах эту связку называют Framework + Skill + Graph. «Framework» там — узкий смысл: слой-схема. В этой базе фреймворк = вся упаковка (схема + skills + проверки), поэтому первая нога зовётся **схемой** — терминологическая каша исключена. Примеры ниже — на [БА-фреймворке](03_БА_фреймворк.md); по тем же правилам в триаду встаёт фреймворк спек.

## Роли

|Нога|Что даёт|Без неё|
|---|---|---|
|**Схема**|типы артефактов, допустимые рёбра, валидные ID|Skill изобретает структуру каждый раз|
|**Skill**|процедуру наполнения схемы|шаблоны мёртвые: описано, что должно получиться, но не как|
|**Граф**|хранилище результата + проверки целостности|impact-анализ невозможен, расхождения накапливаются|

## Где смыкаются

- **Схема** → [БА-фреймворк](03_БА_фреймворк.md): типы артефактов и ID-схемы.
- **Skill** → [04_Claude_Code/01_Основные/04_Skills.md](../04_Claude_Code/01_Основные/04_Skills.md) (механика) + конкретные `ba-*` skills проекта.
- **Граф** → [Граф](02_Граф.md): граф-инструмент над артефактами.

## Конвейер на реальном примере

БА-пайплайн (пример конвейера): каждый шаг — отдельный skill, каждый артефакт — узел графа, каждая ссылка по ID — типизированное ребро.

|Шаг|Skill (процедура)|Артефакт (узел)|Что проверяет граф|
|---|---|---|---|
|Встреча → рафинат|`ba-refine-meeting`|рафинат `[D]/[R]/[PAIN]`|все факты сохранены (самопроверка)|
|Рафинат → стейкхолдеры|`ba-generate-stakeholders`|`ST-XX`|ID уникальны|
|ST → требования|`ba-generate-requirements`|`BR.X`|нет сирот|
|Требования → процессы|`ba-generate-processes`|`BP-XX`|ссылки на `BR.X` валидны|
|Процессы → правила|`ba-generate-rules`|`BR-XX`|нет висячих ID, нет циклов|
|Правила → функции|`ba-generate-functions`|`BF.XX`|coverage: каждое `F` покрыто `BF`/`BR`|

Поток в процессе → [02_БА_документация](../02_Процесс/02_БА_документация.md).

## Что ломается при выпадении одного

- **Убрать схему** → skill каждый раз изобретает форму. Поля у похожих артефактов разные, граф не строится.
- **Убрать skill** → шаблоны мёртвые. Схема описывает, что должно получиться, но не как. Каждый артефакт собирается вручную.
- **Убрать граф** → impact-анализ невозможен. После правки правила неизвестно, какие процессы и спеки протухли. На сотнях артефактов и тысячах связей ручной ревью бесполезен.
