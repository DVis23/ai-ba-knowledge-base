# AI-native разработка

Эта база описывает организацию разработки, в которой ИИ-агенты работают с
проектом через явные источники, контракты, инструменты и проверки.

AI-native подход не равен генерации кода. Он разделяет пять задач:

1. сохранить продуктовый смысл и происхождение решений;
2. зафиксировать требуемое поведение;
3. реализовать типовую и уникальную механику;
4. получить проверяемые доказательства результата;
5. связать артефакты так, чтобы их можно было находить и анализировать.

## Разделение полномочий

| Система | Владеет | Не владеет |
|---|---|---|
| BA-фреймворк | Источниками, решениями, бизнес-правилами и происхождением знаний | Готовностью реализации |
| SDD / OpenSpec | Каноническим поведением продукта и изменениями этого поведения | Платформенной реализацией |
| Декларативная платформа | Повторяемой технической механикой | Продуктовым смыслом |
| Тесты и evals | Доказательствами наблюдаемого результата | Формулировкой требования |
| Граф | Индексом связей, поиском, impact и trace gaps | Каноном и change workflow |
| Агентная среда | Исполнением процедур и доступом к инструментам | Методологией проекта |

Границы важнее названий инструментов. Замена модели, CLI или генератора не
должна менять владельца требования или доказательства.
