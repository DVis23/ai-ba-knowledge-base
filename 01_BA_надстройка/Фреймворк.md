## Общий смысл

Фреймворк для Claude Code решает три проблемы, которые без него неразрешимы:

1. **Стохастичность LLM.** Один и тот же промпт даёт разный результат. Фреймворк фиксирует _форму_ вывода (шаблон + схема), оставляя модели только содержание.
2. **Ограниченный контекст.** Модель не может «держать в голове» весь проект. Фреймворк разрезает знание на адресуемые узлы (артефакты с ID) и связи между ними — LLM подтягивает только нужное.
3. **Невалидируемость свободного текста.** Если артефакт — просто «документ», его нельзя проверить программно. Фреймворк превращает его в _структуру_: предсказуемые секции, типизированные ID, ссылки. Появляется линтер.

По сути это **контракт между людьми, LLM и инструментами**. Без контракта — три стороны не сходятся: человек хочет одно, LLM выдаёт другое, тулинг не понимает ни того, ни другого.

## Как разрабатываются

1. **От боли, а не от шаблона.** Ловится паттерн: «LLM путает BR.X и BR-XX», «теряем источник решения», «после правки рафината не понимаем что устарело». Каждый шаблон рождается как ответ на конкретный сбой.
2. **На индустриальных стандартах.** BPMN, Gherkin, C4, ADR, JSON Schema, ER. Не изобретают нотацию — берут известную и сужают под LLM.
3. **Итеративно, на боевых проектах.** Шаблон попадает в фреймворк, когда переиспользован 2-3 раза с правками. Иначе это просто чей-то черновик.
4. **С двойной аудиторией.** Markdown (человек) + Mermaid (человек+парсер) + явные ID + frontmatter. Никаких PDF и Confluence — LLM должна прочесть нативно.
5. **С тулингом сразу.** Если для шаблона нельзя написать линтер за день — шаблон сырой. Структура должна быть достаточно жёсткой, чтобы её проверял скрипт.

## Принципы

Сквозные, работают для любого фреймворка под Claude Code:

| Принцип                         | Что значит                                                                                   | Что ломается без него                                |
| ------------------------------- | -------------------------------------------------------------------------------------------- | ---------------------------------------------------- |
| **Стабильные ID**               | Артефакты адресуются кодом (BR.19, F-04), не названием                                       | Трассировка распадается после первого переименования |
| **Single source of truth**      | Каждый факт живёт в одном месте, остальные — ссылаются                                       | LLM находит две версии и выбирает случайную          |
| **Двусторонняя трассируемость** | Артефакт знает и предков, и потомков                                                         | Невозможен impact-анализ                             |
| **Атомарность единицы работы**  | Behavior Slice / UC / BR-XX — то, что LLM закрывает за один проход с проверяемым результатом | LLM делает «всю фичу», теряется на полпути           |
| **Машиночитаемость**            | Предсказуемые секции, типизированные блоки, схема                                            | Любая валидация = ручной ревью                       |
| **Валидируемость = линтер**     | Для каждого правила есть автопроверка                                                        | Правила существуют только в голове автора            |
| **Контекстная изоляция**        | LLM подаётся подграф, а не репозиторий                                                       | Контекст переполнен, ответ размыт                    |
| **Decision capture**            | Почему так, а не иначе — отдельный артефакт (ADR, BD)                                        | Через месяц никто не помнит, перерешают заново       |
| **Assume → mark**               | Что LLM придумала — помечено явно (`[ПРЕДПОЛОЖЕНИЕ]` + вопрос)                               | Догадки выглядят как факты, попадают в код           |
| **Dual mode**                   | Каждый skill работает и на создание, и на инкрементальный апдейт                             | После первого прогона фреймворк замораживается       |
| **Idempotency**                 | Повторный запуск не дублирует и не ломает                                                    | Конвейер одноразовый                                 |
| **Конвейерность**               | Артефакты в строгом порядке (рафинат → ST → BR → BP → F → UC → код)                          | Циклические зависимости, генерация «из ничего»       |

## Один способ это запомнить

Фреймворк = **граф адресуемых артефактов + правила его роста + автоматические проверки целостности**. Всё остальное — оформление. Если эти три вещи есть, LLM становится надёжным исполнителем. Если хоть одной нет — генератором случайного текста.
