# Стадия 2. БА-документация

Рафинаты встреч → связный корпус типизированных артефактов бизнес-знания: кто чего хочет, какие процессы, какие правила и числа, какие решения и почему. Это документная семья фреймворков в действии — триада [Схема + Skill + Граф](../03_Фреймворки/01_Триада.md).

## Триада на этой стадии

|Нога|Что делает здесь|
|---|---|
|**Схема**|задаёт типы артефактов, ID-схемы, обязательные секции → [БА-фреймворк](../03_Фреймворки/03_БА_фреймворк.md)|
|**Skill**|`ba-generate-*` наполняет шаблоны по процедуре, шаг за шагом|
|**Граф**|граф-инструмент хранит результат и проверяет целостность → [Граф](../03_Фреймворки/02_Граф.md)|

## Конвейер `ba-pipeline`

Шесть шагов, каждый потребляет выход предыдущего. Оркеструет `ba-pipeline`, останавливаясь после каждого шага для подтверждения:

|#|Skill|Вход|Выход|
|---|---|---|---|
|1|`ba-generate-stakeholders`|рафинаты|`ST-XX` — ожидания стейкхолдеров|
|2|`ba-generate-requirements`|ST + рафинаты|`BR.X` — требования (иерархия)|
|3|`ba-generate-processes`|BR + рафинаты|`BP-XX` — сквозные процессы (E2E)|
|4|`ba-generate-rules`|BP + BR|`BR-XX` — атомарные правила (формулы, вход/выход)|
|5|`ba-generate-functions`|BP + BR + PRD|`BF.XX` — функции (индекс, **не** источник чисел)|

Конвейер **обновляет, а не пересоздаёт**: если артефакт уже есть — режим инкрементального дополнения. Длинный прогон режется на части: `--from requirements --until rules`.

## Параллельные ветки

По ходу конвейера, не строго в нём:

|Skill|Производит|Когда|
|---|---|---|
|`ba-apply-decisions`|`BD-XX` — решения (ADR-подобные, с обоснованием и подписями)|сделан выбор на встрече|
|`ba-extract-domain-model`|`DM/EN/SM` — сущности, справочники, статусные модели|появились данные/статусы|
|`ba-decompose-modules`|`M-XX` — модули приложения|процессы устоялись|
|`ba-generate-gherkin`|Gherkin-фичи (BDD)|правила готовы к проверке|

## Конвенции (обязательны)

Сквозные правила всех BA-скиллов:

- **Lint после правки.** После каждого артефакта: пересобрать граф (`import`) + `lint <ID>`. ERR — исправить до завершения.
- **Стабильные ID.** Уточнил смысл — тот же ID; сменил смысл — новый ID, старый `Deprecated → см. …`.
- **Dual mode.** Skill работает и на создание, и на обновление; чужой контент без основания не трёт.
- **Трекинг предположений.** Догадка — `[ПРЕДПОЛОЖЕНИЕ]` + открытый вопрос + источник допущения. Не выдавать за факт.
- **Бизнес-язык в документах для заказчика.** В Vision/обзорах раздел начинается с эффекта для бизнеса; техника (`webhook`, `outbox`, `retry`) — вторым планом или переведена.

## Граф как контроль качества

После конвейера — реиндексация и глобальная проверка:

```bash
import          # пересобрать graph.db из markdown
lint            # TODO/TBD, висячие ID, циклы, свежесть
audit           # двусторонность ссылок, coverage, аномалии
impact <ID>     # что зависит от артефакта (перед правкой)
```

Граф ловит то, что не видно глазами на сотнях файлов: правило без источника, требование без процесса, расходящиеся числа. Подробно → [Граф](../03_Фреймворки/02_Граф.md).

## Роль корпуса: источник правил, не приёмка

БА-корпус отвечает на «что хочет бизнес и почему» — это **слой расследования** (investigation). Приёмочным каноном он не становится: приёмку несут спеки (AC), которые цитируют решения и правила корпуса как источник. На зрелом проекте активная трассировка приёмки идёт по цепочке «экран → сырые критерии → AC → тест», а БА-слой остаётся источником правил, чисел и контекста — по нему отвечают «почему так», а не «принято ли».

Спутник корпуса — **реестр открытых вопросов**: единый документ с категориями, статусами и владельцами. Каждый `[Q]` рафината и каждое `[ПРЕДПОЛОЖЕНИЕ]` артефакта живут там до закрытия с датой и решением.

## Выход

Корпус артефактов (папка discovery) + индекс в графе (`graph.db`). Каждый артефакт трассируется вверх — к рафинату и решению, вниз — к тому, что из него вырастет. Это вход для [спек и архитектуры](03_Спеки_и_архитектура.md).
