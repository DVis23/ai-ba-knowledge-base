# Платформенный runtime

**Статус:** концептуальный.

Платформенный runtime — общий исполняемый слой. Он превращает декларации и
метаданные в стандартное поведение во время работы приложения.

## Исполнение

**Runtime** — код, загруженный вместе с приложением и участвующий в обработке
реальных запросов, событий и фоновых операций.

**Метаданные** — структурированное описание объекта или операции. Они могут
задавать поля, связи, разрешения и политики.

**Интерпретация** — чтение метаданных и выбор поведения без генерации отдельной
реализации каждого случая.

**Ресурс** — тип данных, над которым доступны стандартные операции: создать,
прочитать, изменить, удалить или найти.

**CRUDL** — сокращение для create, read, update, delete и list. Это базовый
набор операций над коллекцией ресурсов.

## Общие политики

**Политика** — правило, которое runtime одинаково применяет к группе операций.

**Permission** определяет, кто может прочитать данные или выполнить действие.

**Audit** сохраняет факт операции: инициатора, время, объект и изменение.

**Cache** хранит ранее вычисленный результат, чтобы не получать его заново.

**Инвалидация cache** помечает сохранённый результат устаревшим после изменения
исходных данных.

**Idempotency** гарантирует, что повтор одного логического запроса не создаст
повторный эффект.

**FSM** описывает конечный набор состояний объекта и разрешённые переходы.

**Task** — работа, выполняемая вне исходного пользовательского запроса. Она
может пережить перезапуск процесса и повториться после временной ошибки.

**Integration** — управляемая граница с внешней системой: подключение,
аутентификация, вызовы и приём событий.

## Runtime и библиотека

Проект сам вызывает обычную библиотеку. Runtime чаще управляет последовательностью:
получает запрос, читает декларацию, применяет политики и вызывает проектное
расширение.

**Инверсия управления** означает, что общий слой вызывает проектный код в
предусмотренной точке, а не проект вручную собирает весь процесс.

## Цена общего слоя

- ошибка runtime затрагивает многих потребителей;
- обновление требует контракта совместимости;
- скрытая последовательность усложняет диагностику;
- нестандартное поведение требует явных точек расширения;
- продуктовые правила нельзя переносить в общий слой ради удобства.

Runtime оправдан, когда общая политика действительно одинакова для нескольких
ресурсов или проектов.
