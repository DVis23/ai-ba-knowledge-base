# Шаблонизатор с runtime

**Статус:** концептуальный.

В связанной модели шаблонизатор создаёт статическую форму приложения, а runtime
исполняет общие правила. Оба используют одну декларацию или согласованные части
одной модели.

## Два момента выполнения

**Compile time** — подготовка приложения. В этот момент создаются исходные
файлы, типы, миграции и схемы.

**Run time** — работа запущенного приложения. В этот момент обрабатываются
запросы, события и фоновые задачи.

Название compile time здесь не требует настоящей компиляции языка. Оно отделяет
заранее созданный результат от поведения, вычисляемого на работающей системе.

```text
декларация
  ├── генератор → статические артефакты
  └── runtime   → исполняемые политики

статические артефакты + runtime → типовая механика
проектные расширения            → уникальное поведение
```

## Контракт между частями

**Общий контракт** задаёт форматы, интерфейсы и ожидания, по которым
сгенерированный код обращается к runtime.

**Интерфейс** — набор операций и типов данных, доступный одной части системы от
другой. Он описывает возможность вызова, но скрывает внутреннюю реализацию.

**Совместимость версий** означает, что артефакты одной версии генератора могут
работать с указанной версией runtime.

**Миграция контракта** переводит декларации и сгенерированные артефакты на новую
версию без скрытого изменения поведения.

## Разделение ответственности

| Задача | Шаблонизатор | Runtime |
|---|---:|---:|
| Создать структуру пакета | Да | Нет |
| Создать типы и SDK | Да | Нет |
| Подготовить миграцию | Да | Может применить |
| Обработать стандартную операцию | Создаёт адаптер | Исполняет |
| Проверить permission | Связывает декларацию | Исполняет |
| Выполнить audit и idempotency | Подключает | Исполняет |
| Реализовать уникальное правило | Создаёт точку расширения | Вызывает проектный код |

**Адаптер** переводит интерфейс одной части системы в интерфейс другой без
изменения бизнес-смысла.

**Проектное расширение** принадлежит конкретному продукту. Оно реализует
уникальное правило через публичную точку расширения платформы.

## Главный риск

Одна декларация может стать скрытым языком программирования. Если для нового
правила постоянно добавляются флаги, вложенные условия и исключения, правило
нужно вынести в явный проектный код. Декларация должна описывать повторяемую
структуру, а не маскировать произвольную программу.
