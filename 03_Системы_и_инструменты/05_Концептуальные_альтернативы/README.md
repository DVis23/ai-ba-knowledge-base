# Концептуальные альтернативы

Другие системы сохраняются здесь как источники отдельных полезных решений. Они
не образуют обязательные ступени одного процесса и не должны становиться вторым
каноном рядом с уже выбранной SDD-системой.

- [Архитектурный пакет разработки](01_Архитектурный_пакет_разработки.md) связывает
  архитектурные границы, состояния интерфейса и вертикальные срезы реализации.
- [Другие SDD-системы](02_Другие_SDD-системы.md) даёт признаки для сравнения
  change-oriented и living-spec подходов.

Заимствовать следует механизм с понятной задачей: например, State Machine для
сложного экрана или карту файлов для реализации. Копировать весь процесс ради
одного приёма не требуется.
