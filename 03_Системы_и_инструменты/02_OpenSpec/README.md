# OpenSpec

**Статус:** описание конкретной системы.

OpenSpec реализует SDD через два корпуса: принятые спецификации и пакеты
изменений.

**Capability** — связная область поведения, имеющая собственного владельца и
название. Capability может описывать функцию, сквозное правило или внешний
контракт; она не обязана совпадать с экраном.

**Requirement** — отдельное обязательство capability.

**Scenario** — наблюдаемый пример выполнения requirement.

**Delta spec** — только добавляемая, изменяемая или удаляемая часть требований.
Она не копирует living spec целиком.

## Два состояния знания

```text
specs/    принятое текущее поведение
changes/  предлагаемое изменение поведения
```

Пока change обсуждается, его утверждения не являются действующим контрактом.
После проверки реализации дельта синхронизируется с living spec, а change
архивируется.

## Артефакты change

**Proposal** объясняет проблему, границы и ожидаемое изменение.

**Delta specs** фиксируют изменение наблюдаемого поведения.

**Design** описывает технические решения, которые нужны для реализации.

**Tasks** перечисляют исполнимые шаги и проверки.

Разделение не означает четыре обязательных длинных документа. Размер каждого
артефакта соответствует сложности и риску изменения.

## Полномочия

OpenSpec владеет принятым контрактом существенного поведения. Он не владеет
первичными человеческими источниками, кодом и результатами запусков. Ссылки на
них сохраняют происхождение и доказательства, но не переносят полномочие.

Границы применения описаны в [отдельном документе](01_Границы_применения.md).
