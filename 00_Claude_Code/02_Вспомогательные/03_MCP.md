# MCP (Model Context Protocol)

Открытый протокол для tool-серверов, расширяющих Claude. Внешние сервисы регистрируют свои tools — Claude вызывает их так же, как встроенные Read/Edit/Bash.

## Зачем существует

1. **Структурированный доступ к внешнему миру.** Без MCP — оборачиваешь каждый API в CLI и зовёшь через Bash, парся текст. С MCP — типизированный tool с JSON Schema на входе и выходе.
2. **Переносимость.** MCP-сервер работает в Claude Code, Desktop, IDE-плагинах — везде один интерфейс.
3. **Изоляция.** MCP-сервер — отдельный процесс. Падает он — Claude жив. Доступ ограничивается на уровне конфигурации.

## Когда писать свой MCP

- Нужен **доступ к внутренней системе** (CRM, ETL, ML-pipeline), не имеющей стабильной CLI.
- Tool используется **в нескольких проектах** — Bash-обвязка дублируется.
- Нужны **типизированные ответы**, чтобы LLM не ошибалась с парсингом.

## Когда НЕ MCP

- CLI уже есть и стабильна → Bash + jq дешевле.
- Однократная задача → не окупится.
- Tool нужен только в одном проекте и только тебе → локальный skill справится.

## Конфигурация

`settings.json` секция `mcp`:

```json
{
  "mcp": {
    "servers": {
      "linear": {
        "transport": "stdio",
        "command": "linear-mcp-server",
        "args": [],
        "env": { "LINEAR_API_KEY": "..." }
      }
    }
  }
}
```

- **transport** — `stdio` (процесс запускается локально) или `http` (внешний эндпоинт).
- **permissions** — какие tools разрешены, какие требуют подтверждения. Настраивается per-server.

## Безопасность

- MCP-сервер видит то, что ему дали: секреты, API-ключи, файлы.
- **Не подключай неаудированный MCP** в проект с чувствительными данными.
- Проверяй разрешения каждого сервера — не «всё разрешено» по умолчанию.

## Принципы дизайна (для своих серверов)

|Принцип|Что значит|Что ломается без него|
|---|---|---|
|**Узкий tool**|Один tool — одно действие. Не `do_everything(action: enum)`|LLM путает аргументы, ошибается в выборе|
|**Описание = критерий вызова**|Tool description = когда вызывать, не «что это»|Tool есть, но не находится моделью|
|**Структурированный ответ**|JSON-объект, не текст|Парсинг моделью → стохастика|
|**Идемпотентность read-tool**|Чтение не меняет состояние|Дубли при retry|
|**Явные ошибки**|Ошибка — типизированный объект, не throw|Claude не понимает, повторить или нет|

## Связь с другими механизмами

- Agent наследует доступ к MCP-tools — см. [../01_Основные/05_Agents.md](../01_Основные/05_Agents.md). Можно ограничить, кто из агентов их видит.
- Hook ≠ MCP: hook реагирует на событие в сессии, MCP добавляет инструменты. Иногда взаимозаменимы (отправка в Slack — можно тем и другим), но MCP даёт типизированный интерфейс.
